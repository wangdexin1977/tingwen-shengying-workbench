# 新闻数字人

在视频设置中勾选「启用新闻男主播」。使用当前任务已经完成的 MP3 驱动口型，不重新生成声音，不把背景音乐送入口型模型。男性西装半身形象放在左下角，宽度占画面 30%；标题和口播字幕排在右侧区域。数字人写入最终 MP4，工作台播放、全屏和下载后的内容一致。

当前形象采用沉稳的新闻播报表情和自然眨眼；没有实现按文稿语义自动切换喜怒哀乐。也没有实现直播实时数字人。

## 同步与复用

- 输出 1920×1080、25fps。每帧位置来自原音频的绝对采样时间，不使用推理耗时或系统时钟。
- 长音频每段处理 28 秒，保留最多前后各 1 秒上下文；所有段继续使用全局帧号。修正浮点取整导致部分时长少算一帧的问题。
- 确认静音后使用闭口姿态；眨眼只改变眼睑区域，不替代声音驱动的嘴部动画。
- 新音频重新生成口型；仅更换照片、标题、字幕或音乐时复用已验证完整的口型片段。损坏或时长不符的缓存重新生成。
- 支持原有暂停和取消。口型生成失败时保留原音频与已有成片，不输出静态人物冒充成功。
- 工作台记录口型生成耗时；复用时显示首次耗时。原有 MP3 总耗时仍只描述音频生成流程。

## 本机运行环境

模型和独立运行环境保存在 `avatar_runtime/`，已加入 Git 忽略。当前环境使用现有 TTS 环境的只读依赖，不修改原有配音环境。

| --- | --- |
| 口型引擎 | MuseTalk 1.5，MLX fp16，未使用 4/8 位量化 |
| MLX 移植代码 | xocialize/musetalk-mlx，提交 c6eb30ebd1ed4d043983209813370153de9346bf |
| 权重 | mlx-community/MuseTalk-1.5-fp16，修订 ad54104a0129121fe2ea67471250c0656c985284 |
| 核心及辅助权重 | 约 1.884 GB，包括 UNet、VAE、Whisper encoder；不是原始 FP32 的 3.4 GB 文件 |
| 本机依赖 | Python 3.13、MLX 0.31.1、OpenCV 4.11.0、NumPy 2.4.3、librosa 0.11.0 |
| 同步检测 | joonson/syncnet_python，提交 907c0b579c2e2d83f0eae1b2ac9e720cde4e5623 |

原始项目：[MuseTalk](https://github.com/TMElyralab/MuseTalk)、[MLX 移植](https://github.com/xocialize/musetalk-mlx)、[FP16 权重](https://huggingface.co/mlx-community/MuseTalk-1.5-fp16)、[SyncNet](https://github.com/joonson/syncnet_python)。各组件遵循各自授权。主播是本项目生成的虚构人物，素材说明见 `assets/avatar/README.md`。

迁移环境时需保留 `.venv`、`musetalk-core`、`weights-mlx`、`revisions.json`，以及检测所需的 `syncnet` 和 `weights-eval`。更换模型、生成程序或人物配置后，应重新检测并保存 `validated.json`；未完成验证时界面会禁用数字人开关。

## 验证入口

先用同一人声生成口型片段，再导出含人物的最终 MP4：

```sh
avatar_runtime/.venv/bin/python scripts/generate_avatar.py --audio narration.mp3 --out face.mp4
.venv/bin/python scripts/compose_video.py --bg cover.png --audio narration.mp3 --avatar-face face.mp4 --no-subtitle --out presenter.mp4
avatar_runtime/.venv/bin/python scripts/check_avatar_sync.py --video presenter.mp4 --out sync-report.json
```

检测会读取最终 MP4 的实际画面与音轨，分别检查全文、开头、中间、结尾及每个 28 秒分段衔接处，并加入故意延后 400ms 的音轨作为对照。内部验收目标为各段偏移不超过 2 帧、各段间偏移差不超过 2 帧，并检查检测置信度与对照结果。SyncNet 是模型估计，不能替代嘴形、停顿及表情的目视检查。

25 秒云健样片实测：口型生成约 101.9 秒，MLX 峰值内存约 3.97 GB；同步偏移为 0～40ms，延后音轨的对照被识别。该速度来自 M5／24GB 的本次样本，不承诺实时生成，也不代表所有文稿都具有相同效果。

75 秒连续音频实测：1,862 帧，口型生成约 369.4 秒，峰值内存约 3.97 GB；全文、首中尾及 28／56 秒衔接处检测偏移均为 0～40ms。对照音轨增加的 400ms 偏移被正确识别，未见随分段累积的漂移。该长样本由同一段测试播报连续重复三遍组成。

工作台实际操作已验证：载入云健音频、启用数字人、导出与播放器播放正常；更换背景音乐后复用口型，原 MP3 与口型缓存内容不变。152 项回归通过，包含真实媒体帧率读取、缓存损坏重建、标题避让及验证绑定检查。
