# 随机配图实施与验收

用户已确认：默认 7 张，可自定义；工作台提供专用文件夹、一键打开。

使用 writing-plans 梳理并在当前工作区依次实施，复用现有本机照片导入和多图时间线，不修改配音或口型逻辑。

- [x] 在 `random_photos.py` 提供专用目录、计数及不重复抽样。1–50 张整数；忽略隐藏文件、子目录、符号链接、不支持的格式；损坏或超过 20 MB 的图片跳过。数量不足取全部并提示；空目录报错，不启动音频。整批沿用 40 MB 限制。
- [x] 在 `app.py` 接入目录状态、打开目录、随机选择三个接口。选择结果包含原始图片副本的上传数据及小预览，后续用现有上传接口保存，文件夹变化不改变已选素材。
- [x] `templates/index.html`、`static/random-photos.js` 增加随机方式、数量、打开目录、刷新数量、重新抽图、预览；首次生成自动抽图，之后复用预览。现有音频导入及保存队列均使用该批选择。
- [x] `preferences.py`、`static/preferences.js` 保存方式和数量，图片内容不存入配置；`.gitignore` 排除专用目录；更新说明。
- [x] 先写并观察失败的专项测试，再实现；验证默认/自定义数量、不重复、异常图片、文件夹为空或不足、任务及队列冻结图片；真实 FFmpeg 检查随机三图顺序与均分时长。
- [x] 跑隔离回归、浏览器实际检查，服务空闲后重载 8092，确认选项与目录入口正常。

完成标准：用户放入图片后可默认抽 7 张或指定数量，看到实际预览，生成 MP4 覆盖整段音频；后续修改图库不改变已保存的任务及队列。测试素材仅放在诊断目录，不混入用户图库。
